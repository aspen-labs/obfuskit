Cross-Site Scripting (XSS)

Entity encoding bypass: Replace <script> with script to bypass filters
💡 Try: <script>alert(1)</script> or <script>prompt('XSS')</script>
Reflected below. This is intentionally unsafe.

Case Sensitivity Confusion

Different casings of the same parameter key are treated differently
💡 Backend may collapse case-insensitive keys during processing, allowing parameter pollution

Encoding Mismatch (Frontend vs Backend)

Client sends one encoding, backend decodes differently
💡 Try: %253Cscript%253Ealert(1)%253C%2Fscript%253E with url,url decode chain

Unicode and Hex Encoding

Decode sequences like \u003c, \x3c and observe output
💡 Unicode: \u003cimg src=x onerror=alert(1)\u003e | Hex: 3c696d67207372633d78206f6e6572726f723d616c6572742831293e

Mixed / Conflicting Encodings

Apply chained decodes to nested payloads
💡 Try: dGVzdA%3D%3D with url,b64 decode chain | Base64: dGVzdA%3D%3D → test%3D → test=

Inconsistent URL Normalization

Observe how cleaning before/after decoding changes path handling
💡 Try: ..%2Ffiles%2Fsample.txt | Path traversal after URL decode

Path Normalization Discrepancies

UNIX vs Windows separators and double decode bugs
💡 UNIX: ../../../etc/passwd | Windows: ..\\..\\windows\\system32\\drivers\\etc\\hosts

Misparsed JSON / XML Structures

Backend falls back to permissive parsing when Content-Type is not JSON; naive XML entity expansion
💡 JSON: Send form data with text/plain | XML: Use entity expansion for XXE

MIME Sniffing

Sniffed content type overrides declared; HTML gets rendered
💡 Send HTML content with application/octet-stream Content-Type

Loose Regex / Auto-Decoding

Block literal <script but allow double-decoded variants
💡 Try: %253Cscript%253Ealert(1)%253C%2Fscript%253E | Double URL encoded

Header Parsing Ambiguities

First vs last value for duplicate headers
💡 Set duplicate headers: X-Test: one and X-Test: two, then query with pick=last

Cookies Ambiguities

Browsers won't let JS set duplicate Cookie headers. Use this to set a cookie twice (last wins)
💡 Set same cookie twice, then query backend. Try different casings for name.
Tip: After setting, you can also try different casings for name on server (`name=SESSION` vs `session`).

Null Byte & Special Char Injection

Logging vs processing mismatch around null bytes
💡 Try: admin%00root | Null byte terminates string in processing but not in logging

HTTP Parameter Pollution

Multiple instances of the same parameter; backends may pick first or last
💡 Try: a=1&a=2&a=3 | Backend may use first, last, or concatenate values

Semicolon Query Parsing

Treats semicolons as query separators in addition to ampersands
💡 Try: a=1;b=2&also=c | Semicolons may be parsed as parameter separators

Unsafe Upload

Saves uploaded file using provided filename. Try Windows separators and nested paths
💡 Try filename: ../../../etc/passwd or ..\\..\\windows\\system32\\drivers\\etc\\hosts

Unusual HTTP Methods

Override method using header; TRACE echoes headers
💡 Use X-HTTP-Method-Override header to change POST to TRACE

Chained and Nested Payloads

Decode nested encodings in sequence
💡 Try: dGVzdA%3D%3D with url,b64 decode chain | Base64 then URL decode

Overly Trusting Reverse Proxies

Treats X-Forwarded-For client IP as trusted; 127.0.0.1 becomes admin
💡 Try: 127.0.0.1, 1.2.3.4 | First IP in X-Forwarded-For is trusted

Desync Attacks

Hijacks the connection and echoes partial request. Behavior varies behind proxies
💡 May cause connection issues or echo partial request data
